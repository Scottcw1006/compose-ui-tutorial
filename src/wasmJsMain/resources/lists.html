第 4 章 · 狀態與資料

Lazy 列表

告別 RecyclerView、Adapter、ViewHolder 與 DiffUtil。Lazy 系列元件只會組合與排版目前看得到的項目，用幾行程式就能做出可以捲動上千筆資料的列表。

LazyColumn

說明

LazyColumn 的內容區塊是一個 DSL，不是一般的 Composable 區塊：

  • item { }：放單一項目，例如標題或 header。
  • items(list) { }：依資料清單產生項目，可以和 item 自由混用，不用再處理 view type。
  • key：提供穩定的唯一 ID，資料新增、刪除、重新排序時，Compose 才能正確保留每列的狀態與動畫 —— 相當於 DiffUtil 的 areItemsTheSame。

不要在 Column 裡用 forEach 產生大量項目再加 verticalScroll —— 那會一次組合所有項目，等同於把 1000 個 View 放進 ScrollView。

LazyRow

說明

水平方向的版本。注意 contentPadding 和 Modifier.padding 的差別：contentPadding 加在內容的頭尾，捲動時項目可以滑進留白區域，不會被裁切 —— 相當於 RecyclerView 的 clipToPadding="false"。

LazyVerticalGrid

說明

網格版本，取代 GridLayoutManager。GridCells 決定欄位怎麼切：

  • GridCells.Fixed(3)：固定 3 欄。
  • GridCells.Adaptive(72.dp)：每欄至少 72dp，依可用寬度自動決定欄數，在平板與手機上都好看。

捲動狀態與 derivedStateOf

說明

rememberLazyListState() 可以讀取目前捲動位置，也能用程式控制捲動（animateScrollToItem 是 suspend 函式，要用 rememberCoroutineScope 啟動）。

捲動位置每一幀都在變，如果直接在 Composable 裡讀 firstVisibleItemIndex 來判斷要不要顯示按鈕，會造成大量不必要的重組。用 derivedStateOf 包起來，只有在「布林值本身」改變時才會觸發重組。
