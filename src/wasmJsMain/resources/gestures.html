手勢與拖曳

在 View 系統裡，自訂手勢通常要覆寫 onTouchEvent、搭配 GestureDetector、VelocityTracker，自己處理 ACTION_DOWN / MOVE / UP。Compose 把手勢分成三個層級，從簡單到底層依序是：

層級API適用情境
高階 Modifierclickable、draggable、scrollable、transformable單一方向拖曳、捲動、點擊，附帶無障礙支援
手勢偵測器pointerInput { detectTapGestures / detectDragGestures … }雙擊、長按、自由拖曳等組合手勢
底層事件pointerInput { awaitPointerEventScope { … } }完全自訂，相當於 onTouchEvent

detectTapGestures：點擊、雙擊、長按

說明

clickable 只處理單擊。需要區分雙擊或長按時，改用 pointerInput 裡的 detectTapGestures，每個回呼都會拿到點擊位置（相對於元件左上角的 px 座標）。

pointerInput(key) 的 key 和 remember 的 key 意義相同：key 改變時，手勢偵測的協程會被取消並重新啟動。不依賴任何外部值時傳 Unit 即可。

同時加上 onDoubleTap 時，單擊要等一小段時間確認不是雙擊才會觸發，所以會感覺稍有延遲。只需要單擊時，請用 clickable。

detectDragGestures：自由拖曳

說明

detectDragGestures 每次移動都會回傳這一幀的位移量 dragAmount，把它累加到 offset 狀態上就能讓元件跟著手指走。change.consume() 表示「這個事件我處理掉了」，避免父層的捲動容器也同時反應。

注意這裡用的是 Modifier.offset { } 的 lambda 版本：它在排版階段才讀取狀態，拖曳時只會重新擺放位置，不需要重組整個元件。

draggable + animate：滑動刪除

說明

只需要單一方向時，用 Modifier.draggable 比 pointerInput 更簡單。這個範例把手勢與動畫串在一起：

  • 拖曳中：每次位移直接加到 offsetX 狀態上，元件即時跟手。
  • 放開時：onDragStopped 是 suspend lambda，會拿到放開瞬間的速度。拖得夠遠、或甩得夠快就飛出去並刪除，否則彈回原位。
  • suspend 函式 animate(...) 會一路執行到動畫結束才返回，所以寫在它後面的 onDismiss() 一定在飛出動畫播完後才執行。
  • 把放開時的速度傳給 initialVelocity，動畫會延續手指的慣性，而不是從靜止開始。

常見陷阱：若改用 Animatable，並在拖曳回呼裡 scope.launch { snapTo(...) }，最後一次拖曳排程的 snapTo 可能在放開後才執行，把飛出動畫取消掉，元件就會卡在半路、onDismiss 也不會被呼叫。

實務上，Material 3 已經提供 SwipeToDismissBox，一般列表直接使用即可。理解這個範例的原理後，你就能做出卡片堆疊、底部抽屜這類 Material 元件沒有涵蓋的互動。
