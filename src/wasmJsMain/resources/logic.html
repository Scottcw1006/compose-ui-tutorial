Coroutine 邏輯層實戰

Compose UI 教學的第 5 章講的是協程怎麼和畫面接起來。這個單元離開 UI，專心在 Repository、UseCase、ViewModel 這一層：協程怎麼暫停、怎麼取消、例外往哪裡跑、資料流怎麼合併與共享，以及怎麼測試。

範例怎麼看

  • 代碼：純 Kotlin，沒有任何 @Composable。函式都多收一個 log: (String) -> Unit 參數，用來回報發生了什麼；複製到單元測試或 main() 裡，傳 ::println 就能直接執行。
  • 執行結果：右側的深色面板會真的執行同一段代碼。選好情境後按 Run，每一行紀錄前面是從開始算起的毫秒數，[名稱] 依協程上色，方便看出誰在什麼時候做了什麼。

瀏覽器是單執行緒的：範例跑在 WebAssembly 上，所有協程共用同一條執行緒，沒有 Dispatchers.IO，也看不到真正的多執行緒競爭。這反而讓「暫停」與「阻塞」的差別特別明顯。和 Android 行為不同的地方，各節都會特別說明。
