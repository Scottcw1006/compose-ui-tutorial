CCompose 實戰教學

第 7 章 · 動畫與特效

Canvas 自訂繪圖

以前自訂繪圖要繼承 View、覆寫 onDraw(canvas)、自己管理 Paint 物件並記得呼叫 invalidate()。在 Compose 中，繪圖只是一個 Composable 或一個 Modifier，讀取的狀態改變時會自動重畫。

Canvas 與 DrawScope

說明

Canvas 的 lambda 在 DrawScope 裡執行，提供 drawRect、drawCircle、drawLine、drawArc、drawPath 等函式。和舊的 Canvas API 最大的差別：

  • 不需要 Paint：顏色、筆刷、樣式都直接當參數傳入。
  • 座標是 px：DrawScope 本身就是 Density，可以直接呼叫 16.dp.toPx()。
  • size 與 center：隨時可以取得畫布大小與中心點，不用再在 onSizeChanged 裡記錄。
  • 填滿或描邊：預設是填滿，傳入 style = Stroke(...) 改成描邊，取代 Paint.Style.STROKE。

Path：任意形狀

說明

基本圖形不夠用時，用 Path 描述輪廓：moveTo 移動筆尖、lineTo 畫直線、quadraticTo / cubicTo 畫曲線、close 封閉路徑。

同一條 Path 可以畫兩次：一次用漸層 Brush 填滿，一次用 Stroke 描邊。

結合動畫：進度環

說明

Canvas 和動畫是天作之合：把 animateFloatAsState 的值拿來當 sweepAngle，進度改變時圓弧就會平滑地增長或縮短。自訂圖表、儀表板、計時器都是這個模式。

常見陷阱：描邊是沿著路徑中心往兩側擴張的，所以畫圓弧時要往內縮半個筆畫寬度，否則外側會被裁掉。

結合手勢：塗鴉板

說明

把上一章的 detectDragGestures 套在 Canvas 上，記錄手指經過的座標點，每一筆畫轉成一條 Path 畫出來。

已完成的筆畫存在 mutableStateListOf 中：對這種清單呼叫 add、clear 也會被 Compose 觀察到並觸發重畫，不需要整個替換清單。

drawBehind 與 drawWithContent

說明

不一定要用 Canvas。想在既有元件上加一點裝飾，用繪圖 Modifier 更方便：

  • Modifier.drawBehind { }：畫在內容後面，例如螢光筆底線、自訂背景。
  • Modifier.drawWithContent { }：由你呼叫 drawContent()，可以決定裝飾要畫在內容前面還是後面，例如未讀紅點、浮水印。
  • Modifier.drawWithCache { }：需要建立 Path、Brush 這類物件時使用，只在尺寸或讀取的狀態改變時重建，避免每一幀都配置新物件。

其實 Canvas(modifier) { } 的實作就是 Spacer(modifier.drawBehind { })。所以 Canvas 本身沒有大小，一定要透過 Modifier 指定尺寸，否則什麼都看不到。
