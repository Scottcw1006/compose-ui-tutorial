測試協程

協程的程式碼充滿 delay、逾時與平行執行。直接在測試裡跑，要嘛很慢，要嘛結果時好時壞。kotlinx-coroutines-test 用「虛擬時間」解決這兩個問題。這一章只有代碼，測試對象就是前面幾章的範例函式。

runTest 與虛擬時間

說明

把測試包在 runTest { } 裡，delay 就不會真的等待：排程器直接把虛擬時鐘撥到下一個該發生的時間點。所以第 1 章要跑 1.2 秒的 loadDashboard，在測試裡幾毫秒就結束，而 currentTime 仍然精確地顯示 1200。時間是確定的，平行執行的先後順序也就固定了，可以放心斷言。

DashboardTest.kt
// build.gradle.kts
// testImplementation("org.jetbrains.kotlinx:kotlinx-coroutines-test:<版本>")

class DashboardTest {
    @Test
    fun loadsUserAndFeedInParallel() = runTest {
        val logs = mutableListOf<String>()
        val screen = loadDashboard { logs += "$currentTime $it" }

        assertEquals("user + feed", screen)
        // 平行執行：ready 出現在 900ms（較慢的 feed），而不是 600 + 900
        assertContains(logs, "900 [dashboard] ready: user + feed")
        // coroutineScope 會等 analytics 結束才返回
        assertEquals(1200, currentTime)
    }

    @Test
    fun collectLatestOnlyRendersTheLastReading() = runTest {
        val logs = mutableListOf<String>()
        consume(Strategy.CollectLatest) { logs += it }

        assertEquals(listOf("[ui] rendered 6"), logs.filter { "rendered" in it })
        assertEquals(900, currentTime) // 6 × 100ms + 最後一筆的 300ms
    }

    @Test
    fun supervisorScopeKeepsOtherDownloads() = runTest {
        val logs = mutableListOf<String>()
        downloadAll(supervised = true) { logs += it }

        assertContains(logs, "[a.png] downloaded")
        assertContains(logs, "[c.png] downloaded")
        assertContains(logs, "[handler] b.png: HTTP 500")
    }
}

需要在中途檢查狀態時，自己推動時鐘：

  • advanceTimeBy(500)：往前推 500ms，執行這段期間該發生的工作。
  • runCurrent()：只執行「現在」這個時間點已經排好的工作。
  • advanceUntilIdle()：一直執行到沒有任何待辦工作為止。

注入 Dispatcher 與測試 ViewModel

說明

虛擬時間只管得到跑在測試排程器上的協程。程式裡寫死的 Dispatchers.IO 是真的執行緒，測試就失去控制，這就是第 4 章把 dispatcher 當成建構子參數的原因。ViewModel 用的 Dispatchers.Main 在單元測試裡不存在（沒有 Android Looper），要用 Dispatchers.setMain 換掉，通常包成一個 JUnit Rule：

GalleryViewModelTest.kt
class MainDispatcherRule(
    val testDispatcher: TestDispatcher = UnconfinedTestDispatcher(),
) : TestWatcher() {
    override fun starting(description: Description) = Dispatchers.setMain(testDispatcher)
    override fun finished(description: Description) = Dispatchers.resetMain()
}

class GalleryViewModelTest {
    @get:Rule
    val mainRule = MainDispatcherRule()

    @Test
    fun syncShowsProgressUntilDone() = runTest {
        // 所有 dispatcher 共用 runTest 的排程器，才能用同一個虛擬時鐘控制
        val testDispatcher = StandardTestDispatcher(testScheduler)
        val repo = PhotoRepository(
            api = FakePhotoApi(latencyMs = 1_000),
            dao = FakePhotoDao(),
            ioDispatcher = testDispatcher,
            defaultDispatcher = testDispatcher,
        )
        val viewModel = GalleryViewModel(repo)

        viewModel.onSyncClick()
        assertTrue(viewModel.uiState.value.syncing) // Unconfined：launch 立刻執行到第一個暫停點

        advanceTimeBy(999)
        assertTrue(viewModel.uiState.value.syncing) // 假 API 還沒回應

        advanceUntilIdle()
        assertFalse(viewModel.uiState.value.syncing)
    }
}

測試 stateIn 的 Flow：WhileSubscribed 的 StateFlow 沒人收集時不會更新。在測試裡用 backgroundScope.launch { viewModel.uiState.collect() } 開一個收集者，它會在測試結束時自動取消，不會讓 runTest 一直等下去。
